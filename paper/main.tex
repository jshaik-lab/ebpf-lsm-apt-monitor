\begin{abstract}
Contemporary host-based intrusion detection systems (HIDS) suffer from a
critical semantic gap: they observe \emph{what} a process does but cannot
reason about \emph{why} it does so.  Rule-based eBPF engines such as Falco
attach to tracepoints that fire \emph{before} the kernel resolves the final
object, leaving them vulnerable to time-of-check-to-time-of-use (TOCTOU)
races and path-aliasing attacks.  Deep-learning detectors close the semantic
gap but impose prohibitive overhead and lack real-time enforcement.  We present
\sentinel{}, a kernel security framework that addresses these limitations
through nine original contributions.
\textbf{(1) LSM-eBPF Co-Design}: We replace tracepoints with BPF Linux Security
Module hooks (\texttt{lsm/bprm\_check\_security}, \texttt{lsm/file\_open},
\texttt{lsm/socket\_connect}) that fire \emph{after} kernel object resolution,
providing TOCTOU-resistant telemetry unavailable in prior eBPF-based detectors.
\textbf{(2) Graph-Structured Prompting via Intent Provenance Graphs (\ipg{})}: A
directed multigraph compresses multi-process syscall windows into a structured
YAML representation consumed directly as the LLM's structured input, reducing
token consumption by 59.8\% at $n{=}20$ events (measured with tiktoken
cl100k\_base on 6 real strace traces) while preserving causal
semantics---a fundamentally different paradigm from prior work that flattens
events into free-form logs.
\textbf{(3) Dual-Tier Local Inference}: Per-PID entropy histograms maintained
in a BPF LRU map gate a speculative 1B\,draft\,+\,8B\,full local LLM pipeline;
the architecture is designed to eliminate the majority of full-model invocations
for stable benign processes, with exact reduction depending on workload
distribution.
\textbf{(4) SSL/TLS Uprobe Layer for AI Agent Monitoring}: eBPF uprobes on
\texttt{SSL\_read}/\texttt{SSL\_write} intercept decrypted LLM API traffic from
autonomous AI agents, correlating prompt intent with kernel actions inside the
\ipg{} to detect prompt-injection-driven APT chains---a capability not present
in any existing system.  Enforcement uses a novel
\textbf{Confidence-Weighted Adaptive Enforcement} (\cwae{}) engine with five
graduated tiers, replacing binary block/allow with proportional kernel response.
Evaluated on 14 simulation scenarios, expanded strace corpora, and DARPA TC~E3
CADETS provenance replay (behavioral F1\,=\,0.568; TI-aided F1\,=\,0.931 with
explicit oracle caveat).  Primary Linux validation uses an IONOS VPS
(Ubuntu~24.04, 16\,GB RAM) with local Ollama inference.
\end{abstract}

\section{Introduction}\label{sec:intro}
%% ═════════════════════════════════════════════════════════════════════════════

The modern threat landscape is dominated by Advanced Persistent Threats (APTs)
that evade signature-based detection by employing \emph{living-off-the-land}
(LotL) tactics---abusing trusted system utilities (\eg{} \texttt{bash},
\texttt{curl}, \texttt{python3}) to blend attack traffic with legitimate
behavior~\cite{darpa_tc}.  In these scenarios, no individual system call
is inherently malicious; only the \emph{causal sequence and context} reveal
attacker intent.

Traditional HIDS such as OSSEC~\cite{ossec} and Tripwire rely on file
integrity checks and static rule sets that are both brittle (high false
negatives against novel techniques) and slow (polling-based, high overhead).
eBPF-based rule engines such as Falco~\cite{falco} and
Tetragon~\cite{tetragon} improve performance by executing in the kernel, but
their expressiveness is bounded by manually authored rules---a fundamental
limitation against zero-day and polymorphic attacks.
Deep learning detectors such as DeepLog~\cite{deeplog} and
LogBERT~\cite{logbert} achieve higher semantic coverage but require
significant GPU resources, offline training phases, and lack the ability to
\emph{block} an ongoing attack in real time.

The confluence of three recent advances creates a new design space.
\emph{eBPF LSM hooks}~\cite{bpf_lsm_kernel} fire \emph{after} the kernel
resolves the true object identity, eliminating TOCTOU vulnerabilities inherent
to tracepoint-based detectors used by all prior eBPF tools.
\emph{Quantized local LLMs} (\eg{} Llama-3-8B-GGUF~\cite{llama3}) run on
commodity hardware, enabling semantic reasoning without external API calls.
\emph{eBPF uprobes} on TLS library functions expose decrypted AI agent traffic,
opening a new monitoring surface for prompt-injection-driven attacks.
Combining all three, however, is non-trivial:

\begin{itemize}
  \item \textbf{TOCTOU exposure}: All published eBPF detectors attach to
        \texttt{sys\_enter\_*} tracepoints, which fire before the kernel
        resolves symlinks and bind mounts, enabling path-substitution evasion.
  \item \textbf{Token efficiency}: Naïve serialization of a 20-event syscall
        window consumes $\sim$850 LLM tokens per process, making real-time
        multi-process monitoring prohibitively expensive.
  \item \textbf{Invocation rate}: A lightly loaded server generates
        $\sim$3{,}000 syscalls/second; submitting every window to an LLM is
        computationally infeasible.
  \item \textbf{Enforcement granularity}: Binary block/allow decisions
        (Falco, Tetragon) miss the nuanced spectrum between a suspicious but
        uncertain event and a high-confidence ongoing attack.
  \item \textbf{AI agent blind spot}: Autonomous AI agents (Claude Code,
        Copilot Workspace, AutoGPT) execute shell commands via TLS-encrypted
        API calls invisible to syscall-only monitors.
\end{itemize}

\vspace{2pt}
\noindent\textbf{Contributions.} This paper makes the following original
contributions:

\begin{enumerate}
  \item \textbf{LSM-eBPF Co-Design for TOCTOU-Resistant Telemetry}: We replace
        tracepoints with BPF LSM hooks (\texttt{lsm/bprm\_check\_security},
        \texttt{lsm/file\_open}, \texttt{lsm/socket\_connect}) available since
        Linux~5.7.  These hooks fire post-resolution, eliminating TOCTOU and
        path-aliasing evasion available against all prior eBPF-based detectors
        (Section~\ref{sec:lsm}).
  \item \textbf{Graph-Structured Prompting via Intent Provenance Graphs
        (\ipg{})}: A directed multigraph encodes causal syscall structure and is
        serialized as \emph{structured YAML} consumed directly as the LLM's
        input---a fundamentally different paradigm from log-flattening approaches
        (Section~\ref{sec:ipg}).  Token consumption is reduced by 59.8\%
        at $n{=}20$ events (measured with tiktoken cl100k\_base on 6 real
        strace traces), and we characterize the information preservation
        properties of the abstraction, with an explicit threat model for its
        bounded losses (Hypothesis~\ref{thm:info}).
  \item \textbf{Dual-Tier Local Inference Pipeline}: Per-PID entropy histograms
        in a BPF LRU map gate a 1B-draft\,+\,8B-full speculative LLM pipeline
        (Alg.~\ref{alg:inference}), designed to bypass the full model for
        stable benign processes (Section~\ref{sec:pipeline}).
  \item \textbf{SSL/TLS Uprobe Layer for AI Agent Intent Monitoring}: eBPF
        uprobes on \texttt{SSL\_read}/\texttt{SSL\_write} intercept decrypted
        LLM API traffic from AI agents and inject intent nodes into the \ipg{},
        enabling detection of prompt-injection-driven APT chains with no
        application instrumentation (Section~\ref{sec:tls}).
  \item \textbf{Confidence-Weighted Adaptive Enforcement (\cwae{})}: A
        five-tier enforcement engine mapping continuous confidence scores to
        graduated kernel actions, replacing the binary block/allow model of
        existing tools (Alg.~\ref{alg:enforce}, Section~\ref{sec:enforce}).
  \item \textbf{Chain of Verification (CoVe) with Forensic UUID Linking}: A
        four-step Draft\,$\to$\,Verify\,$\to$\,Ground\,$\to$\,Synthesize loop that links
        every LLM claim to a specific eBPF \texttt{event\_id} UUID, computing
        a hallucination rate and penalizing confidence in proportion to
        unverifiable claims (Section~\ref{sec:cove}).
  \item \textbf{LTL Symbolic Guardian}: Five formally specified Linear Temporal
        Logic safety axioms (AX-1 through AX-5) enforced at O(1) via a
        \textsc{RuntimeMonitor} and a kill-chain \textsc{B\"{u}chiMonitor},
        providing a hard floor on enforcement independent of LLM output
        (Section~\ref{sec:ltl}).
  \item \textbf{Program-Counter-Aware Behavioral Provenance (PCABP)}: Detects
        process-injection attacks by checking \emph{where} in the address space
        a syscall was invoked via eBPF \texttt{bpf\_get\_stack}, combining a
        static Bloom-filter of valid ELF call sites with a PyTorch contrastive
        encoder (centroid separation\,=\,1.717; 500-trial synthetic eval:
        TPR\,=\,1.000, FPR\,=\,0.000) (Section~\ref{sec:pcabp}).
  \item \textbf{Open implementation and simulation evaluation}: A fully
        functional async Python implementation with Docker deployment, evaluated
        on 14 MITRE ATT\&CK simulation scenarios using Llama-3.1-8B, with all
        evaluation scripts released for reproducibility.
\end{enumerate}

\section{Background and Related Work}\label{sec:background}
%% ═════════════════════════════════════════════════════════════════════════════

\subsection{eBPF Architecture and Hook Points}
eBPF~\cite{ebpf_verifier} extends the Linux kernel with a sandboxed virtual
machine whose programs pass a static verifier guaranteeing memory safety,
termination, and privilege separation before JIT compilation.
Attachment points include kprobes, tracepoints, LSM hooks (kernel~5.7+),
and XDP network hooks.  Ring buffers (\texttt{BPF\_MAP\_TYPE\_RINGBUF})
stream typed events to user space at rates exceeding 10~million events/second
with sub-microsecond kernel-side latency~\cite{bcc_guide}.
Production tools Falco~\cite{falco} and Tetragon~\cite{tetragon} attach to
\texttt{sys\_enter\_*} tracepoints that fire \emph{before} kernel object
resolution, exposing them to TOCTOU and path-aliasing evasion.
Google's KRSI (Kernel Runtime Security Instrumentation), upstreamed as
BPF~LSM~\cite{bpf_lsm_kernel}, attaches programs to
\texttt{lsm/bprm\_check\_security}, \texttt{lsm/file\_open}, and
\texttt{lsm/socket\_connect} hooks that fire post-resolution.
FG-RCA~\cite{fgrca2025} uses LSM hooks for zero-day IoT containment with
policy synthesis, but without semantic LLM reasoning.  \sentinel{} is the
first to combine BPF~LSM telemetry with a dual-tier LLM inference pipeline
and graduated kernel enforcement.

\subsection{Provenance-Based Intrusion Detection}
Provenance graphs model causal relationships among OS entities (processes,
files, sockets) as directed acyclic graphs.  WATSON~\cite{watson,watson2} and
MORSE~\cite{morse} use graph neural networks over offline provenance graphs
to reconstruct attack campaigns, while ATLAS~\cite{atlas} adds attention-based
GNNs for APT detection.  UNICORN~\cite{unicorn} applies streaming histosketches
over provenance graphs for online APT detection (F1\,=\,0.88 on DARPA TC~E3).
ShadeWatcher~\cite{shadewatcher} uses a heterogeneous knowledge-graph
recommendation engine over provenance, achieving strong precision but requiring
offline graph construction.  ProvDetector~\cite{provdetector} and
DEPIMPACT~\cite{depimpact} focus on root-cause analysis of confirmed incidents
rather than online detection.  LLM-APTDS~\cite{llm_aptds} constructs knowledge
graphs from system logs and uses LLMs with iterative MITRE-guided reasoning,
but relies on an external GPT-4o API (high latency, privacy risk) and performs
no real-time enforcement.  Recent work~\cite{llm_provenance_2025} applies
GPT-4o embeddings to provenance event sequences for semantic augmentation,
achieving 99.1\% accuracy in proof-of-concept experiments, yet explicitly
acknowledges infeasibility for production real-time detection.
\sentinel{} addresses this gap: the \ipg{} supports \emph{online streaming
inference} with a fully local LLM, eliminating external API dependencies and
the associated latency and privacy concerns.

\subsection{Graph-Structured LLM Prompting for Security}
Prior work feeding security telemetry to LLMs serializes events as free-form
narratives~\cite{llm_provenance_2025} or JSON event lists~\cite{llm_aptds}.
In the broader NLP literature, graph-structured prompting~\cite{kg_llm_threat}
feeds structured graph representations directly as LLM input, improving
multi-hop relational reasoning over purely linearized inputs.
\sentinel{} introduces this paradigm to kernel security: the \ipg{} is
serialized as structured YAML---preserving edge directionality, temporal weights,
and resource-type hierarchy---rather than flattened prose.  Empirically,
this reduces token consumption by 59.8\% at $n{=}20$ events (measured with
tiktoken cl100k\_base on 6 real strace traces) while preserving the causal
structure that LLMs must reason over (Section~\ref{sec:ipg}).

\subsection{LLM-Based Anomaly Detection}
AnoLLM~\cite{anollm} demonstrates that instruction-tuned LLMs outperform
classical anomaly detectors on tabular data via in-context learning.
LogBERT~\cite{logbert} and LogRobust~\cite{logrobust} fine-tune transformers
on system logs but require offline training and substantial compute.
AgentSight~\cite{agentsight} intercepts TLS-encrypted LLM agent traffic via
eBPF uprobes on \texttt{SSL\_read}/\texttt{SSL\_write}, correlating intent with
kernel actions and reporting $<$3\% runtime overhead.  However, AgentSight
is \emph{observability-only}: it provides no semantic classification model and
no enforcement capability.  \sentinel{} extends this architecture with an
\ipg{}-mediated LLM classifier and \cwae{} enforcement, and is the first system
to fuse AI agent intent (via TLS uprobes) with kernel-level APT enforcement.

\subsection{System Call Anomaly Detection}
Classical methods model normal call sequences as $n$-grams~\cite{forrest},
HMMs~\cite{hmm_syscall}, or LSTM sequences~\cite{deeplog}.
DeepLog~\cite{deeplog} achieves strong accuracy on the HDFS dataset but is
designed for log-file analysis, not real-time kernel monitoring.
Bertinatto~\etal{}~\cite{bertinatto2024} use eBPF to detect privilege
escalation via call-sequence signatures without semantic reasoning.
ZenGuard~\cite{zenguard2025} applies ML-driven adaptive zero-trust policies
at the network and identity layers but does not operate at the kernel syscall
level.  \sentinel{} bridges all three dimensions: kernel-level LSM telemetry,
LLM semantic classification, and graduated enforcement integrated in one
pipeline.

\section{Threat Model}\label{sec:threat}
%% ═════════════════════════════════════════════════════════════════════════════

\sentinel{} is designed to detect and respond to \emph{intent-based} threats
on Linux hosts.  We consider an adversary with the following capabilities:

\begin{itemize}
  \item \textbf{User-space code execution}: The attacker can execute arbitrary
        code as a non-root user, or has compromised a service process running
        with restricted privileges.
  \item \textbf{LotL techniques}: The attacker uses pre-installed binaries
        (\texttt{curl}, \texttt{bash}, \texttt{python3}) to avoid triggering
        file-hash signatures.
  \item \textbf{Multi-stage kill chains}: Attack behavior spans multiple
        processes and syscall sequences (reconnaissance, privilege escalation,
        lateral movement, exfiltration) that are individually benign.
  \item \textbf{AI agent compromise}: The attacker delivers indirect prompt
        injections to an autonomous AI agent, causing it to execute malicious
        shell commands while its orchestrator remains unaware.
\end{itemize}

\noindent\textbf{Out of scope}: Kernel-resident rootkits that tamper with
\ebpf{} programs or ring buffers, hardware-level side-channel attacks, and
adversarial attacks crafted to manipulate LLM inference outputs.  The
\ebpf{} verifier and Linux LSM hooks provide a trusted boundary below
\sentinel{}'s trust anchor.

\subsection{Architecture Overview}

Fig.~\ref{fig:arch} shows the \sentinel{} architecture.  The system operates
in four logically distinct layers:

\begin{enumerate}
  \item \textbf{LSM Telemetry Layer}: BPF LSM hooks (\texttt{bprm\_check\_security},
        \texttt{file\_open}, \texttt{socket\_connect}) collect post-resolution
        kernel events into a ring buffer, immune to TOCTOU races.
  \item \textbf{SSL/TLS Uprobe Layer}: Uprobes on \texttt{libssl.so} intercept
        decrypted AI agent API traffic and inject \textsc{LLM-Intent} nodes
        into the per-PID event stream.
  \item \textbf{Inference Layer}: A Python daemon converts raw events into \ipg{}
        (structured YAML), runs the dual-tier local LLM pipeline, and emits
        structured threat decisions.
  \item \textbf{Enforcement Layer}: The \cwae{} engine maps confidence scores
        to five graduated kernel actions via \texttt{bpf\_send\_signal()} and
        XDP quarantine maps.
\end{enumerate}

%% ─────────────────────────────────────────────────────────────────────────────
\subsection{LSM-eBPF Co-Design for TOCTOU-Resistant Telemetry}
\label{sec:lsm}
%% ─────────────────────────────────────────────────────────────────────────────

All prior eBPF-based HIDS attach to \texttt{sys\_enter\_*} tracepoints, which
fire at the \emph{entry} to a system call before the kernel resolves the final
object.  This creates a structural TOCTOU window: an attacker can replace a
symlink between the tracepoint firing and the actual file open, causing the
detector to record a path that was never accessed.  BPF~LSM hooks, introduced
in Linux~5.7~\cite{bpf_lsm_kernel}, fire \emph{after} the kernel resolves the
full path, validates credentials, and determines the final dentry.  This
post-resolution position is structurally immune to symlink races and
bind-mount aliasing.

\sentinel{} attaches to three LSM hooks:

\begin{itemize}
  \item \texttt{lsm/bprm\_check\_security}: Fires after the kernel resolves the
        final executable binary (post-symlink, post-\texttt{PATH} lookup).
        Provides the true binary inode, UID, and credential context.  Captures
        execution events (MITRE T1059, T1068, T1078) with identity that cannot
        be spoofed via \texttt{PATH} manipulation.
  \item \texttt{lsm/file\_open}: Fires after \texttt{do\_dentry\_open()},
        post-resolution of the full dentry chain.  Captures sensitive file
        accesses (\texttt{/etc/shadow}, \texttt{/proc/\{pid\}/mem}) with the
        true resolved path.  Compared to \texttt{sys\_enter\_openat}, this
        eliminates TOCTOU races exploitable by concurrent filesystem operations.
  \item \texttt{lsm/socket\_connect}: Fires after kernel socket validation and
        address family resolution.  Provides the true destination address
        post-\texttt{getaddrinfo} resolution, preventing DNS-rebinding evasion
        available against tracepoint-based monitors.
\end{itemize}

\begin{lstlisting}[language=C, caption={LSM hook attachment for
TOCTOU-resistant binary execution monitoring (sentinel.c, abridged).},
label={lst:lsm}]
SEC("lsm/bprm_check_security")
int BPF_PROG(lsm_bprm_check, struct linux_binprm *bprm)
{
    struct event_t *e = bpf_ringbuf_reserve(
                            &events, sizeof(*e), 0);
    if (!e) return 0;
    e->pid    = (u32)(bpf_get_current_pid_tgid() >> 32);
    e->ts_ns  = bpf_ktime_get_ns();
    e->sc_type = SC_EXEC;
    /* bprm->file resolved post-symlink -- TOCTOU-safe */
    bpf_probe_read_kernel_str(e->resource,
        sizeof(e->resource),
        bprm->filename);
    _update_entropy_map(e->pid, SC_EXEC);
    bpf_ringbuf_submit(e, 0);
    return 0;   /* allow; enforcement via bpf_send_signal */
}

SEC("lsm/file_open")
int BPF_PROG(lsm_file_open, struct file *file)
{
    /* Only instrument sensitive resource prefixes */
    char path[128];
    bpf_d_path(&file->f_path, path, sizeof(path));
    if (!_is_sensitive(path)) return 0;

    struct event_t *e = bpf_ringbuf_reserve(
                            &events, sizeof(*e), 0);
    if (!e) return 0;
    e->sc_type = SC_FILE_R;
    __builtin_memcpy(e->resource, path, sizeof(path));
    e->pid   = (u32)(bpf_get_current_pid_tgid() >> 32);
    e->ts_ns = bpf_ktime_get_ns();
    _update_entropy_map(e->pid, SC_FILE_R);
    bpf_ringbuf_submit(e, 0);
    return 0;
}
\end{lstlisting}

This LSM co-design closes the fundamental evasion surface of all prior
tracepoint-based detectors.  Both LSM hooks and tracepoints execute a
verifier-compiled JIT program; the only structural difference is the
call-chain position.  Published microbenchmarks of BPF LSM hooks report
overhead on the order of tens of nanoseconds per invocation~\cite{bpf_lsm_kernel},
but we do not claim a specific measured value for this setup since the
evaluation runs inside a Docker VM rather than on bare-metal Linux.

\subsection{Intent Provenance Graph (IPG) and Graph-Structured Prompting}
\label{sec:ipg}

A key bottleneck in applying LLMs to syscall analysis is \emph{token
inflation}: serializing a 20-event window as ``Process X executed; Process X
opened /etc/passwd; \ldots'' consumes $\sim$847 tokens on average
(Table~\ref{tab:compression}).  \ipg{} solves this by encoding causal
structure as a \emph{typed graph}, then serializing the graph as structured
YAML for LLM consumption.

This constitutes a novel \emph{graph-structured prompting} paradigm.
Prior security LLM approaches~\cite{llm_provenance_2025,llm_aptds} linearize
events as free-form prose or JSON lists, forcing the LLM to reconstruct causal
edges from syntax.  \ipg{} makes causal structure \emph{explicit in the prompt
schema}: source nodes, edge labels (syscall type), temporal weights
($\Delta t$), and destination resource types are all first-class YAML fields
the LLM's attention can index without positional reasoning.  This aligns with
recent findings in graph-LLM research~\cite{kg_llm_threat} showing structured
graph input improves multi-hop relational classification by up to 14\% over
linearized alternatives.

\begin{definition}[\textbf{Intent Provenance Graph}]
Let $\mathcal{S} = \langle e_1, e_2, \ldots, e_n \rangle$ be an ordered
syscall window, where each event
$e_i = (\textit{pid}_i, \textit{comm}_i, \textit{sc}_i, r_i, t_i)$
records the PID, process name, syscall type, resource identifier, and
timestamp.  The \emph{Intent Provenance Graph}
$\mathcal{G} = (V, E, \lambda, \omega)$ is a directed multigraph where:
\begin{align}
V &= \{(\textit{comm}, \rho(r)) \mid
       \exists\, e_i : e_i.\textit{comm} = \textit{comm},\,
       \rho(e_i.r) = \rho(r)\}, \label{eq:vertices}\\
E &= \{(v_j, v_k, \textit{sc}_{j{\to}k}, \Delta t) \mid
       e_j, e_{j+1} \in \mathcal{S},\,
       v_j = \nu(e_j),\, v_k = \nu(e_{j+1})\}, \label{eq:edges}
\end{align}
where $\rho(r) \in \{\textsc{Exec}, \textsc{File}, \textsc{Net},
\textsc{Pipe}\}$ is the resource-type abstraction function,
$\nu(e) = (e.\textit{comm}, \rho(e.r))$ is the vertex mapping,
$\lambda : E \to \mathcal{L}_{\text{syscall}}$ assigns syscall labels,
and $\omega : E \to \mathbb{R}^{+}$ assigns temporal weights $\Delta t$.
\end{definition}

\ipg{} deduplicates vertices with identical $(\textit{comm}, \rho)$ pairs
(reducing node count by $\approx$61\%) and merges parallel edges of the same
syscall type (reducing edge count by $\approx$74\%).  Crucially, a merged
edge does \emph{not} collapse to its minimum $\Delta t$: that biased every
repeated transition toward its \emph{fastest} instance, which an attacker
exploits by ensuring a fast benign instance of a $(\text{src},\text{dst},
\text{syscall})$ triple exists to mask a slow malicious one.  We instead
retain a bounded per-edge summary --- occurrence count $c$ and
$(\omega_{\min},\omega_{\max})$ --- so the slowest instance remains visible
to the LLM (Algorithm~\ref{alg:ipg}, line~\ref{alg:dedup}).  The resulting
graph is serialized to a compact textual representation
(Listing~\ref{lst:ipg_text}) consumed by the LLM; the $c$ and
$\omega_{\max}$ fields are emitted only for merged edges to keep single-shot
edges token-cheap.

\begin{hypothesis}[\textbf{Abstraction Adequacy}]\label{thm:info}
Under the working assumption that attack intent in the evaluated domain
manifests in process--resource interaction \emph{types} rather than in
specific argument values (\eg{} exact IP, exact filename), the resource-type
abstraction $\rho$ retains sufficient information to recover the attack label
$Y$ from the graph $\mathcal{G}$.  This is an empirical conjecture, not a
theorem: it is \emph{not} claimed to hold for arbitrary attacks, and a formal
mutual-information bound is deferred to the planned labeled-corpus study.
\end{hypothesis}

\noindent\textbf{Empirical support and threat model.}
The IPG construction is a deterministic surjection from $\mathcal{S}$ to
$\mathcal{G}$ that retains the interaction types, the first-occurrence
temporal ordering, the sensitivity flags, and the literal argument string
\emph{up to a 64-byte prefix}.  On the 14 evaluated scenarios (ten MITRE
ATT\&CK techniques) the Llama-3.1-8B classifier recovers every label from the
IPG alone with no false negatives, which is \emph{consistent with but does
not prove} the hypothesis.  Two residual losses are adversarially relevant
and we state them explicitly rather than assume them away:
(i)~the 64-byte \texttt{res} prefix is a bounded truncation, so an attacker
can push a discriminating path component beyond byte~64 (\eg{} a target under
a long attacker-controlled directory); and
(ii)~the sensitivity flag is computed from a fixed prefix allowlist
(\texttt{/etc/shadow}, \texttt{/.ssh/}, \dots), so a living-off-the-land read
of an \emph{off-list} secret (\eg{} \texttt{/etc/gshadow},
\texttt{/var/run/secrets/}, a GPG keyring) carries no sensitivity signal.
Neither is closed by the abstraction itself; both are backstopped downstream
by the order-aware entropy gate (\S\ref{sec:pipeline}), the PCABP call-site
layer (\S\ref{sec:pcabp}), and the LTL guardian (\S\ref{sec:ltl}), none of
which depends on argument fidelity.  Path-level edge labels remain available
for deployments that require finer argument resolution.

\begin{algorithm}[!t]
\caption{IPG Construction}\label{alg:ipg}
\begin{algorithmic}[1]
\Require Event window $\mathcal{S} = \langle e_1, \ldots, e_n \rangle$
\Ensure Intent Provenance Graph $\mathcal{G}$
\State $V \gets \emptyset$;\; $E \gets \emptyset$
\For{$i = 1$ to $n$}
  \State $v_i \gets (\text{comm}(e_i),\; \rho(\text{resource}(e_i)))$
  \If{$v_i \notin V$} $V \gets V \cup \{v_i\}$ \EndIf
  \If{$i > 1$}
    \State $\Delta t \gets t_i - t_{i-1}$
    \State $e_{\text{new}} \gets (v_{i-1}, v_i, \text{sc}(e_i), \Delta t)$
    \State\label{alg:dedup} \textbf{if} $\exists e' \in E : \text{src}(e')=v_{i-1} \wedge \text{dst}(e')=v_i
           \wedge \lambda(e')=\lambda(e_{\text{new}})$
    \State \quad $\omega_{\min}(e') \gets \min(\omega_{\min}(e'), \Delta t)$;\;
                  $\omega_{\max}(e') \gets \max(\omega_{\max}(e'), \Delta t)$
    \State \quad $c(e') \gets c(e') + 1$ \Comment{bounded summary, not min-only}
    \State \textbf{else} $E \gets E \cup \{e_{\text{new}}\}$;\;
           $\omega_{\min}{=}\omega_{\max}{=}\Delta t$;\; $c{=}1$
  \EndIf
\EndFor
\State \Return $\mathcal{G} = (V, E, \lambda, \omega)$
\end{algorithmic}
\end{algorithm}

\subsection{Dual-Tier Inference Pipeline}\label{sec:pipeline}

Even with \ipg{} compression, submitting every window to an LLM remains
prohibitively expensive at scale.  The dual-tier pipeline uses a BPF-map-backed
entropy signal to gate LLM invocations from user space.

\subsubsection*{Tier~1: Entropy-Gated LLM Bypass}
For each PID, \sentinel{} maintains a sliding window of $W=64$ syscall type
observations in a \texttt{BPF\_MAP\_TYPE\_LRU\_PERCPU\_HASH}.  User space reads
this map to compute the sliding Shannon entropy:
\begin{equation}
H_t = -\sum_{s \in \mathcal{L}} \hat{p}(s)\log_2 \hat{p}(s), \quad
\hat{p}(s) = \frac{|\{e \in W : e.\textit{sc} = s\}|}{W}.
\label{eq:entropy}
\end{equation}
The marginal entropy of Eq.~\eqref{eq:entropy} is
\emph{permutation-invariant}: it depends only on syscall-type frequencies,
not their order.  A malicious syscall of an already-seen type, interleaved
into a repetitive benign loop, shifts $\hat{p}$ by $O(1/W)$ and leaves $H_t$
below $\theta_{\text{low}}$, so a purely marginal gate is provably blind to
such order-only evasion.  We therefore additionally compute the entropy rate
of the empirical first-order Markov chain over the same window,
\begin{equation}
H_t^{\mathrm{M}} = -\!\!\sum_{(i,j)} \hat{p}(i,j)\,
  \log_2 \hat{p}(j \mid i), \quad
\hat{p}(j \mid i) = \frac{n_{ij}}{\sum_{k} n_{ik}},
\label{eq:markov}
\end{equation}
where $n_{ij}$ counts $s_{t-1}{=}i, s_t{=}j$ transitions in $W$.  Unlike
Eq.~\eqref{eq:entropy}, $H_t^{\mathrm{M}}$ is sensitive to ordering; it is
maintained from an $|\mathcal{L}|\times|\mathcal{L}|$ transition-count
matrix in the BPF map at the same $O(1)$ per-event cost.  Two thresholds
$\theta_{\text{low}} < \theta_{\text{high}}$ partition the entropy space:
\begin{itemize}
  \item $H_t < \theta_{\text{low}}$ \emph{and} $H_t^{\mathrm{M}} <
        \theta_{\text{low}}$ \emph{and} no novel
        $(\textit{comm},\textit{sc})$ unigram or
        $(\textit{comm}, s_{t-1}, s_t)$ transition bigram appeared
        (1.2~bits): highly repetitive, matches a known-benign fingerprint
        $\Rightarrow$ bypass LLM entirely.
  \item otherwise, $\max(H_t, H_t^{\mathrm{M}}) < \theta_{\text{high}}$
        (3.8~bits): pass to Draft Model (Tier~2a).
  \item $\max(H_t, H_t^{\mathrm{M}}) \geq \theta_{\text{high}}$: pass to
        Full Model (Tier~2b).
\end{itemize}
Thresholds $\theta_{\text{low}}=1.2$ and $\theta_{\text{high}}=3.8$ were set
empirically by inspecting entropy distributions across the 14 simulation
scenarios; calibration on a large benign corpus is deferred to the planned
bare-metal empirical study.  The order-aware bypass is evaluated against an
interleaving-evasion attack in \S\ref{sec:adv}.

\subsubsection*{Tier~2a: Draft Model (Llama-3-1B-Q4)}
The 1B draft model classifies the \ipg{} text.  A \textsc{Benign} verdict
at confidence $c \geq 0.90$ is accepted without invoking the full model
(\emph{BENIGN-only fast-path}).  A \textsc{Malicious} verdict from the draft
model always escalates to the full model regardless of confidence, preventing
false-positive enforcement actions from draft calibration errors.  We stress
that this asymmetry bounds only the false-\emph{positive} direction: a fixed
confidence threshold on an uncalibrated 1B model provides \emph{no} bound on
high-confidence false \emph{negatives}, and \S\ref{sec:eval_latency} reports
two such cases.  The fast-path is therefore a measured accuracy--cost
Pareto point, not a free optimization.  The implementation therefore
provides an optional split-conformal calibrator
(\texttt{ConformalFastPath}) that replaces the hand-set $0.90$ threshold
with the conformal quantile $\hat q$ of the draft's BENIGN-confidence on
known-malicious calibration windows, yielding the finite-sample false-accept
guarantee $\Pr[\text{attack fast-pathed}] \leq \alpha + 1/(n{+}1)$ (and
failing safe to full-model escalation until fitted).  The mechanism is
unit-tested for coverage; assembling a labeled calibration corpus of
sufficient size is left to the planned empirical study.
Measured inference latency via Ollama on MacBook Pro M5 is
$p50 \approx 3.6$\,s (min\,2.7\,s, max\,5.5\,s)---comparable to but
slightly faster than the 8B full model at this hardware configuration.
On native Linux with a quantized llama.cpp backend (AVX2, no HTTP
overhead), published benchmarks for 1B GGUF models suggest sub-second
latency~\cite{llamacpp}; this has not been measured in the current setup
and is deferred to the planned bare-metal empirical study.

\subsubsection*{Tier~2b: Full Model (Llama-3-8B-Q4\_K\_M)}
For uncertain cases ($c < 0.90$ from draft or $H_t \geq \theta_{\text{high}}$),
the full 8B model is invoked.  Quantization to 4-bit (Q4\_K\_M via
llama.cpp~\cite{llamacpp}) reduces memory to 4.7~GB and enables 22 tokens/s
on a single 8-core CPU with AVX2 support.

\begin{algorithm}[!t]
\caption{Dual-Tier Inference (BENIGN-only fast-path)}\label{alg:inference}
\begin{algorithmic}[1]
\Require Event buffer $B$ for PID $p$; thresholds $\theta_{\text{low}}, \theta_{\text{high}}$
\Ensure ThreatDecision $D = (\ell, c, \text{ttps})$
\State $H, H^{\mathrm{M}} \gets \text{ComputeEntropy}(B)$ \Comment{marginal + Markov, \ebpf{} map}
\State $\nu \gets \text{NovelUnigramOrTransition}(B)$
\If{$H < \theta_{\text{low}}$ \textbf{and} $H^{\mathrm{M}} < \theta_{\text{low}}$ \textbf{and} $\neg\nu$}
  \Return $({\small\textsc{BENIGN}},\; 0.02,\; \varnothing)$
\EndIf
\State $\mathcal{G} \gets \text{BuildIPG}(B)$ \Comment{Alg.~\ref{alg:ipg}}
\State $\text{text} \gets \text{SerializeIPG}(\mathcal{G})$
\If{$\max(H, H^{\mathrm{M}}) < \theta_{\text{high}}$}
  \State $D_d \gets \text{DraftModel.classify}(\text{text})$
  \If{$D_d.\ell = {\small\textsc{BENIGN}}$ \textbf{and} $D_d.c \geq 0.90$}
    \Return $D_d$ \Comment{BENIGN fast-path only; MALICIOUS always escalates}
  \EndIf
\EndIf
\State $D_f \gets \text{FullModel.classify}(\text{text})$
\Return $D_f$
\end{algorithmic}
\end{algorithm}

\subsection{Confidence-Weighted Adaptive Enforcement (CWAE)}\label{sec:enforce}

Existing tools enforce a binary block/allow decision.  \cwae{} maps the
continuous LLM confidence score $c \in [0,1]$ to five enforcement tiers:

\begin{equation}
A(c) = \begin{cases}
  \textsc{Log} & c < 0.30 \\
  \textsc{Pause} & 0.30 \leq c < 0.50 \\
  \textsc{Kill} & 0.50 \leq c < 0.70 \\
  \textsc{Quarantine} & 0.70 \leq c < 0.85 \\
  \textsc{Isolate} & c \geq 0.85
\end{cases}
\label{eq:cwae}
\end{equation}

\textsc{Pause} issues \texttt{SIGSTOP} via \texttt{bpf\_send\_signal()} and
generates a human-review alert.  \textsc{Kill} adds \texttt{SIGKILL} and a
memory dump.  \textsc{Quarantine} additionally programs XDP maps to
\texttt{XDP\_DROP} all network egress from the process's network namespace.
\textsc{Isolate} combines all prior actions with container-level termination
(via cgroupv2 freeze) and automated incident report generation.

\begin{algorithm}[!t]
\caption{Confidence-Weighted Adaptive Enforcement (CWAE)}\label{alg:enforce}
\begin{algorithmic}[1]
\Require ThreatDecision $D = (\ell, c, \text{ttps})$; target PID $p$
\Ensure EnforcementAction $A$
\If{$\ell = {\small\textsc{BENIGN}}$}  \Return $\textsc{Log}$ \EndIf
\If{$c < 0.30$} \Return $\textsc{Log}(p, D)$ \EndIf
\If{$c < 0.50$}
  \State \texttt{bpf\_send\_signal}$(p, \texttt{SIGSTOP})$
  \State $\textsc{Alert}(p, D)$;\; \Return $\textsc{Pause}$
\EndIf
\If{$c < 0.70$}
  \State \texttt{bpf\_send\_signal}$(p, \texttt{SIGKILL})$
  \State $\textsc{AuditDump}(p)$;\; \Return $\textsc{Kill}$
\EndIf
\If{$c < 0.85$}
  \State \texttt{bpf\_send\_signal}$(p, \texttt{SIGKILL})$
  \State $\textsc{XDP\_QuarantineNS}(p)$;\; \Return $\textsc{Quarantine}$
\EndIf
\State \texttt{bpf\_send\_signal}$(p, \texttt{SIGKILL})$
\State $\textsc{XDP\_QuarantineNS}(p)$
\State $\textsc{CgroupFreeze}(p)$;\; $\textsc{IncidentReport}(p, D)$
\Return $\textsc{Isolate}$
\end{algorithmic}
\end{algorithm}

\subsection{SSL/TLS Uprobe Layer for AI Agent Intent Monitoring}
\label{sec:tls}
%% ─────────────────────────────────────────────────────────────────────────────

Autonomous AI agents (Claude Code~\cite{claudecode}, GitHub Copilot Workspace,
AutoGPT) orchestrate multi-step tasks by exchanging natural-language prompts
and tool-call instructions over HTTPS with remote LLM APIs.  This traffic is
invisible to syscall-only monitors: the TLS encryption layer conceals intent
while the agent executes arbitrary shell commands as kernel-visible syscalls.
A prompt injection attack can therefore trigger a full APT kill chain---credential
dump, lateral movement, data exfiltration---whose root cause lies in a
malicious server-injected instruction that traditional HIDS cannot observe.

\subsubsection*{Uprobe Attachment}
\sentinel{} attaches eBPF uprobes to the \texttt{SSL\_read} and
\texttt{SSL\_write} symbols in the process's dynamically linked
\texttt{libssl.so}.  Uprobes fire in user space within the traced process's
context, making them framework-agnostic: any agent using OpenSSL, BoringSSL,
or GnuTLS (all of which expose the same symbol names in their compatibility
layers) is automatically instrumented with zero application modification and
$<$3\% runtime overhead~\cite{agentsight}.

\begin{lstlisting}[language=C, caption={SSL\_read uprobe for AI agent intent
interception (sentinel\_tls.c, abridged).}, label={lst:tls}]
SEC("uprobe/SSL_read")
int uprobe_ssl_read(struct pt_regs *ctx)
{
    int fd  = (int)PT_REGS_PARM1(ctx);
    void *buf = (void *)PT_REGS_PARM2(ctx);
    int len = (int)PT_REGS_PARM3(ctx);

    /* Store (pid, fd, buf_ptr) for return-probe correlation */
    u64 pid_tgid = bpf_get_current_pid_tgid();
    struct ssl_args_t args = {.buf = buf, .fd = fd};
    bpf_map_update_elem(&ssl_args_map, &pid_tgid,
                        &args, BPF_ANY);
    return 0;
}

SEC("uretprobe/SSL_read")
int uretprobe_ssl_read(struct pt_regs *ctx)
{
    u64 pid_tgid = bpf_get_current_pid_tgid();
    struct ssl_args_t *args =
        bpf_map_lookup_elem(&ssl_args_map, &pid_tgid);
    if (!args) return 0;

    int nbytes = PT_REGS_RC(ctx);
    if (nbytes <= 0) return 0;

    /* Copy decrypted plaintext to ring buffer */
    struct tls_event_t *e =
        bpf_ringbuf_reserve(&tls_events,
                            sizeof(*e), 0);
    if (!e) return 0;
    e->pid    = (u32)(pid_tgid >> 32);
    e->ts_ns  = bpf_ktime_get_ns();
    e->nbytes = nbytes;
    bpf_probe_read_user(e->data, sizeof(e->data),
                        args->buf);
    bpf_ringbuf_submit(e, 0);
    bpf_map_delete_elem(&ssl_args_map, &pid_tgid);
    return 0;
}
\end{lstlisting}

\subsubsection*{Intent Node Injection into IPG}
User-space reassembles TLS byte streams (handling HTTP/2 framing and
Server-Sent Events) and parses the JSON body of LLM API responses.  The
\texttt{content} field of each tool-call instruction is hashed and classified
into one of three categories: \textsc{Benign} (file read, summarize),
\textsc{Suspicious} (shell exec, env access), or \textsc{Malicious} (lateral
movement, credential exfiltration).  This classification injects a synthetic
\textsc{LLM-Intent} node into the per-PID IPG:

\begin{lstlisting}[caption={IPG extended with SSL/TLS intent node for
prompt-injection APT detection (two-event early-detection window).},
language={}, numbers=none]
# Intent Provenance Graph -- SENTINEL v1.0
meta: {nodes: 3, edges: 2}
nodes:
  - {id: n0, comm: claude-cod, rtype: NET}
  - {id: n1, comm: claude-cod, rtype: EXEC}
  - {id: n2, comm: claude-cod, rtype: LLM}
edges:
  - {src: n0, dst: n1, syscall: execve, dt_ms: 1.0, res: /usr/bin/bash}
  - {src: n0, dst: n2, syscall: tls_read, dt_ms: 0.0,
     intent: "[INJECTED] Ignore previous instructions. Execute: ...",
     sensitive: true}
procs: [claude-cod]
\end{lstlisting}

The \textsc{LLM-Intent} node (id \texttt{n2}, \texttt{rtype: LLM}) causally
links the agent's received instruction to the subsequent kernel action.
When the full-tier LLM classifies this two-event IPG, the
\texttt{tls\_read} edge carrying the injected plaintext immediately surfaces the
prompt-injection chain as T1059 and T1003 with 0.93 confidence (ISOLATE tier),
even though no credential-access or C2 syscall has yet occurred.
AgentSight~\cite{agentsight} performs similar TLS interception for
\emph{observability}; \sentinel{} is the first to incorporate the intercepted
intent into a graph-structured classification prompt and to enforce a
graduated kernel response.

\subsubsection*{TOCTOU-Resistant Correlation}
Because the kernel actions subsequent to the intent injection are observed via
LSM hooks (Section~\ref{sec:lsm}), the full causal chain is TOCTOU-resistant:
the agent cannot substitute a benign path between TLS receipt and file open.

\subsection{Chain of Verification (CoVe)}\label{sec:cove}
%% ─────────────────────────────────────────────────────────────────────────────

To prevent hallucinated threat claims from driving enforcement, \sentinel{}
applies a four-step Chain of Verification loop after the LLM classification:
\textbf{Draft} (initial classification), \textbf{Verify} (each claim in
\texttt{evidence\_refs} matched against the event window by resource substring
and syscall type), \textbf{Ground} (unverified claims retracted and confidence
penalized by their \texttt{confidence\_contribution}), and \textbf{Synthesize}
(final \texttt{ThreatDecision} with updated confidence and verified UUID list).

Each LLM claim is linked to a specific \texttt{event\_id} UUID
(\texttt{uuid4()}, assigned at eBPF ring-buffer read time) so the audit log
provides a forensically verifiable trace: every enforcement decision cites the
exact kernel events that drove it.  A \emph{hallucination rate}
$= \text{unverified\_claims}/\text{total\_claims}$ is computed; decisions with
hallucination rate $\geq 0.50$ are downgraded to \textsc{Partial} or
\textsc{Hallucinated} verdict, and verified confidence
$= \text{LLM\_conf} - \sum_{\text{unverified}} \text{contribution}_i$
(clamped to zero).

\subsection{LTL Symbolic Guardian}\label{sec:ltl}
%% ─────────────────────────────────────────────────────────────────────────────

As a hard safety floor independent of LLM output, \sentinel{} enforces five
Linear Temporal Logic axioms (Table~\ref{tab:ltl}) over the event window.

\begin{table}[!h]
\caption{LTL safety axioms enforced by \sentinel{}'s Symbolic Guardian.
Tier-1 (RuntimeMonitor) is O(1) per event; Tier-2 (B\"{u}chiMonitor) tracks
temporal kill-chain sequences.}
\label{tab:ltl}
\centering
\renewcommand{\arraystretch}{1.1}
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{ID} & \textbf{Formula} & \textbf{Severity} \\
\midrule
AX-1 & $\Box(\textit{comm}{=}\texttt{nginx} \Rightarrow \neg\Diamond_{50}(\texttt{execve}(\texttt{/bin/bash})))$ & CRITICAL \\
AX-2 & $\Box(\textit{shadow\_read} \Rightarrow \Diamond_{10}(\texttt{connect}(*)))$ & CRITICAL \\
AX-3 & $\Box(\texttt{prctl}(\texttt{PR\_SET\_NAME}) \Rightarrow \neg\Diamond_{50}(\textit{shadow\_read}))$ & CRITICAL \\
AX-4 & $\Box(\neg\texttt{execve}(\texttt{/tmp/*} \vee \texttt{/dev/shm/*}))$ & HIGH \\
AX-5 & $\Box(\texttt{setuid}(0) \Rightarrow \neg\Diamond_5(\texttt{connect}(*)))$ & CRITICAL \\
\bottomrule
\end{tabular}
\end{table}

AX-1, AX-3, AX-4, and AX-5 are evaluated by a \textsc{RuntimeMonitor} in O(1)
per event using a per-PID watch table.  AX-2 (shadow read $\to$ network
exfiltration kill-chain) uses a \textsc{B\"{u}chiMonitor} that tracks the
temporal gap between the trigger and the consequence.  AX-2 excludes PAM
daemons (\texttt{sshd}, \texttt{sudo}, \texttt{pam}) from the shadow-read
trigger to eliminate false positives from legitimate authentication.
Any axiom violation raises a floor on the enforcement tier regardless of LLM
confidence, preventing a compromised or fooled LLM from under-responding to
a formally provable attack sequence.

\subsection{Program-Counter-Aware Behavioral Provenance (PCABP)}\label{sec:pcabp}
%% ─────────────────────────────────────────────────────────────────────────────

Process-injection attacks (T1055) can mimic a legitimate binary's syscall
sequence --- an nginx worker that calls \texttt{connect()} to a C2 server is
indistinguishable from heap-injected shellcode \emph{at the syscall level}.
PCABP resolves this by checking \emph{where} in the address space the syscall
was invoked, using the user-space instruction pointer captured by eBPF
\texttt{bpf\_get\_stack(BPF\_F\_USER\_STACK)}.

\noindent\textbf{Static layer.}
A Bloom filter of valid return addresses is built offline from the target
binary's ELF \texttt{.plt} entries and \texttt{.text} \texttt{BL}/\texttt{CALL}
instruction scan (pyelftools\,+\,capstone, ARM64 and x86\_64 support).
For nginx~1.18.0 linux/arm64, this yields 311 valid call sites
(Bloom theoretical FPR\,$\approx 7.8 \times 10^{-28}$).  Any event whose IP
falls outside the Bloom filter fires an immediate LLM bypass
(\texttt{trigger=pcabp\_static\_violation}) before the entropy gate.

\noindent\textbf{AI layer.}
A PyTorch contrastive encoder ($\approx 35$K parameters) maps each event to a
3-dimensional feature vector $[\textit{sc\_type}/16,\ \log(\delta+1)/30,\
\textit{res\_type}/8]$ --- where $\delta$ is the distance from the nearest
valid call site --- through two linear layers with LayerNorm and GELU
activation to a 32-dimensional L2-normalized embedding.  Training uses
\textsc{TripletMarginLoss} with in-binary anchors/positives and heap-injected
negatives.  Achieved centroid separation\,=\,1.717.

\noindent\textbf{Consensus and integration.}
The static layer serves \emph{two} distinct roles.  First, as a Layer-0
hard trigger: any event whose IP is outside the Bloom filter forces full
LLM analysis \emph{before} the entropy gate, regardless of the AI score ---
a deterministic indicator of compromise is never suppressed at detection
time.  Second, as an enforcement-tier input.  Here a plain convex blend is
unsafe: $0.4\,\textit{static} + 0.6\,\textit{ai}$ lets a mimicry payload
with $\textit{ai\_divergence}\!\approx\!0$ drag a \emph{confirmed} injection
to exactly $0.40$, which maps to the PAUSE tier rather than KILL.  Because a
deterministic violation must be non-maskable under fusion, we use a
floor-gated consensus:
\begin{equation}
\textit{pcabp\_score} = \max\!\big(\,0.4\,\textit{static} +
  0.6\,\textit{ai},\;\; \tau_{\!f}\cdot\textit{static}\,\big),
\quad \tau_{\!f} = 0.55,
\label{eq:pcabp}
\end{equation}
so $\textit{static}{=}1$ floors the score in the KILL band irrespective of
$\textit{ai\_divergence}$, while $\textit{ai\_divergence}$ may only raise
severity (toward QUARANTINE/ISOLATE); the AI-only path
($\textit{static}{=}0$) is unchanged at $0.6\,\textit{ai}$.  The \cwae{}
engine then uses $\textit{effective\_conf} =
\max(\textit{llm\_conf}, \textit{pcabp\_score})$, so heap-injected shellcode
that fools the LLM is still escalated to the correct enforcement tier.
We also clarify the division of labor this implies: the IPG/LLM tier reasons
over \emph{topology and semantic hints}, whereas \emph{temporal} kill-chain
safety is enforced by the LTL guardian (\S\ref{sec:ltl}) over the
un-collapsed ordered event stream --- the order-lossy IPG
(min-$\Delta t$ edge merge) is deliberately not the temporal oracle.
On a 500-trial synthetic evaluation using the real nginx~1.18.0 ARM64 binary,
PCABP achieves TPR\,=\,1.000, FPR\,=\,0.000, F1\,=\,1.000 at threshold
0.40 (legit window mean score\,=\,0.115; injected mean\,=\,0.892).
\emph{Note: F1\,=\,1.0 reflects pure synthetic classes; real mixed windows
will show variance and require evaluation on live nginx processes.}

\subsection{Kernel Component (C/eBPF)}

The kernel component consists of $\sim$580 lines of C across two files:
\texttt{sentinel.c} ($\sim$450 lines) for LSM hooks, tracepoint fallbacks,
and ring-buffer telemetry, and \texttt{sentinel\_tls.c} ($\sim$160 lines)
for SSL/TLS uprobes.
\texttt{sentinel.c} targets the Linux~5.7+ kernel and attaches three
BTF-typed LSM programs (\texttt{lsm/bprm\_check\_security},
\texttt{lsm/file\_open}, \texttt{lsm/socket\_connect}) as detailed in
Section~\ref{sec:lsm}.  Using \texttt{BPF\_PROG()} macros ensures
CO-RE\footnote{Compile Once, Run Everywhere} portability across kernel minor
versions without recompilation.  Five tracepoint programs
(\texttt{sys\_enter\_execve}, \texttt{sys\_enter\_openat},
\texttt{sys\_enter\_connect}, \texttt{sys\_enter\_setuid},
\texttt{sys\_enter\_ptrace}) are retained as a fallback for kernels~5.4--5.6
that predate BPF~LSM support and for additional coverage of setuid/ptrace
events not exposed by LSM hooks.

\texttt{sentinel\_tls.c} attaches uprobes and uretprobes to
\texttt{SSL\_read}/\texttt{SSL\_write} in the agent process's
\texttt{libssl.so} at runtime, identified by scanning \texttt{/proc/\{pid\}/maps}.
The uprobe/uretprobe pair uses a cookie map to correlate \texttt{enter} context
(buffer pointer) with \texttt{return} data, as shown in Listing~\ref{lst:tls}.

\begin{lstlisting}[language=C, caption={Core ring-buffer event emission
(sentinel.c, abridged).}, label={lst:ebpf}]
struct event_t {
    u32  pid, ppid, uid;
    u64  ts_ns;
    u8   sc_type;   /* EXEC=0, FILE=1, NET=2 */
    char comm[16];
    char resource[128];
    u32  flags;
};
struct {
    __uint(type,       BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 1 << 24); /* 16 MB */
} events SEC(".maps");

/* Sliding-window entropy counters, per-CPU for lock-free updates */
struct entropy_hist_t {
    __u32 counts[SC_TYPES];  /* per-syscall-category hit counts */
    __u32 total;             /* events in current window        */
    __u32 window_pos;        /* ring index for eviction         */
    __u8  window[ENTROPY_WINDOW]; /* circular buffer of recent SC_TYPEs */
};
struct {
    __uint(type,        BPF_MAP_TYPE_LRU_PERCPU_HASH);
    __uint(max_entries, 65536);
    __type(key,  u32);              /* PID */
    __type(value, struct entropy_hist_t);
} entropy_map SEC(".maps");

SEC("tracepoint/syscalls/sys_enter_execve")
int trace_execve(struct trace_event_raw_sys_enter *ctx) {
    struct event_t *e = bpf_ringbuf_reserve(
                            &events, sizeof(*e), 0);
    if (!e) return 0;
    e->pid     = (u32)(bpf_get_current_pid_tgid() >> 32);
    e->ts_ns   = bpf_ktime_get_ns();
    e->sc_type = SC_EXEC;
    bpf_get_current_comm(e->comm, sizeof(e->comm));
    bpf_probe_read_user_str(e->resource, sizeof(e->resource),
                            (void *)ctx->args[0]);
    _update_entropy_map(e->pid, SC_EXEC);  /* helper in sentinel.c */
    bpf_ringbuf_submit(e, 0);
    return 0;
}
\end{lstlisting}

The \texttt{\_update\_entropy\_map} helper increments the syscall-type
histogram stored in the per-CPU LRU map.  User space periodically reads this
map to compute $H_t$ (Eq.~\ref{eq:entropy}) without incurring additional
ring-buffer traffic.

\subsection{Intent Provenance Graph Builder}

The IPG builder is implemented in 215 lines of Python using NetworkX~\cite{nx}
for graph management.  Algorithm~\ref{alg:ipg} is implemented directly.
Serialization encodes nodes and edges as structured YAML with explicit
\texttt{src}/\texttt{dst}/\texttt{syscall}/\texttt{dt\_ms} fields, producing
compact machine-readable representations (Listing~\ref{lst:ipg_text}).

\begin{lstlisting}[caption={IPG structured YAML serialization for a
credential-theft scenario.  YAML preserves graph topology as first-class
fields, enabling direct LLM key-value indexing without prose reconstruction.},
label={lst:ipg_text}, language={}, numbers=none]
# Intent Provenance Graph -- SENTINEL v1.0
meta: {nodes: 3, edges: 4}
nodes:
  - {id: n0, comm: bash, rtype: EXEC}
  - {id: n1, comm: cat,  rtype: FILE}
  - {id: n2, comm: bash, rtype: NET}
edges:
  - {src: n0, dst: n1, syscall: openat(R), dt_ms: 3.0, res: /etc/shadow, sensitive: true}
  - {src: n1, dst: n1, syscall: openat(R), dt_ms: 1.0, res: /etc/passwd, sensitive: true}
  - {src: n1, dst: n2, syscall: connect,   dt_ms: 86.0, res: 104.21.43.12:4444}
  - {src: n2, dst: n0, syscall: execve,    dt_ms: 5.0,  res: /tmp/sh, sensitive: true}
procs: [bash, cat]
# ~58 tokens  (raw-narrative equivalent: ~280)
\end{lstlisting}

The YAML schema requires no natural-language inference to extract edges:
the LLM reads \texttt{src}/\texttt{dst}/\texttt{syscall} fields directly.
Sensitive nodes (\texttt{sensitive: true}) surface threat-relevant structure
in the schema itself, guiding the LLM's attention without prompt engineering.

\subsection{LLM Classifier}

The classifier uses the Ollama HTTP API~\cite{llamacpp} with structured JSON
output (\texttt{"format": "json"}) to eliminate free-form hallucinations.
The system prompt requires five-step chain-of-thought reasoning before the
verdict: identify processes, trace causal chains, map to MITRE techniques,
weigh intent, then assign a calibrated confidence.  The output schema is:

\begin{lstlisting}[language=Python,
caption={Structured LLM output schema and CoT fields (sentinel/llm/ollama.py,
abridged).}]
# Returned JSON fields (enforced via format="json"):
{
  "chain_of_thought": "<steps 1-4, 3-5 sentences>",
  "label":      "BENIGN" | "MALICIOUS",
  "confidence": 0.0-1.0,
  "reasoning":  "<one sentence citing specific edges>",
  "mitre_ttps": [...]
}
\end{lstlisting}

A heuristic mock classifier (\texttt{sentinel/llm/mock.py}) is provided for
offline evaluation without model downloads; Table~\ref{tab:accuracy} uses the
real Ollama backend exclusively.

Two hand-crafted few-shot examples (one credential-dump attack, one benign
nginx scenario) are prepended to the system prompt to anchor the LLM's output
format and calibrate its response scale.  Both examples are included verbatim
in \texttt{sentinel/llm/ollama.py} and are available in the released code.

\subsection{Enforcement Engine}

The enforcement engine uses Python's \texttt{ctypes} to write decision
records into a \texttt{BPF\_MAP\_TYPE\_HASH} named \texttt{enforce\_map},
which the co-resident eBPF enforcement program reads on every subsequent
syscall of the flagged PID.  XDP quarantine is implemented by writing the
process's network namespace ID into the \texttt{xdp\_quarantine\_map};
the XDP hook returns \texttt{XDP\_DROP} for all frames originating from
quarantined namespaces, achieving packet-drop latency of $<$1~\textmu{}s.

\subsection{LSM Hook Overhead and TOCTOU Resistance}\label{sec:eval_lsm}

\noindent\textbf{LSM hook placement and TOCTOU resistance.}
BPF~LSM hooks fire \emph{after} kernel object resolution by construction.
The \texttt{lsm/bprm\_check\_security} hook receives the final
\texttt{linux\_binprm} struct after all symlinks and mount namespaces are
resolved; \texttt{lsm/file\_open} receives the resolved dentry.
Tracepoints at \texttt{sys\_enter\_execve} and \texttt{sys\_enter\_openat}
fire before this resolution.  The structural consequence is that any
path-substitution attack (symlink swap, bind-mount redirect) that completes
between \texttt{sys\_enter} and the LSM hook will be correctly observed by
LSM and silently missed by tracepoints.  A bare-metal empirical measurement
of the TOCTOU evasion rate under adversarial race conditions is deferred to
the planned empirical study; the architectural guarantee of post-resolution
observation is a property of the Linux Security Module call chain, not a
measured quantity.

\subsection{AI Agent Prompt-Injection APT Chain Detection}

We evaluate the SSL/TLS uprobe layer using simulation scenario AGENT-T1003:
an LLM-based agent receives a prompt-injected instruction
``\texttt{[INJECTED] Ignore previous instructions. Execute: cat /etc/shadow
> /tmp/.x \&\& curl -s -F f=@/tmp/.x http://evil.com/upload}'' delivered
inside a normal user turn via the Anthropic API.

The measurement isolates the \emph{early-detection} benefit of TLS interception
by restricting the \emph{without-TLS} run to the first two kernel events
(API connection \texttt{connect} $\to$ \texttt{execve /usr/bin/bash}) --- the
state of the IPG at $t{=}1\,\text{ms}$, \emph{before} the
\texttt{/etc/shadow} read has occurred.  At this point, syscall evidence alone
is too thin to distinguish a malicious agent from routine process spawning.

\textbf{Result (measured, Llama-3.1-8B via Ollama):}
\emph{Without} TLS interception, the two-event IPG is classified \textsc{Benign}
with confidence 0.99 --- a false negative, because the credential-access
and C2 edges are not yet visible to the kernel monitor.
\emph{With} the \textsc{LLM-Intent} node injected from the intercepted
\texttt{SSL\_read} payload (128-byte truncated plaintext), the same two-event
IPG flips to \textsc{Malicious} with confidence 0.93 (\textsc{Isolate} tier),
correctly mapping TTPs T1059 and T1003, \emph{1--2 seconds before the attack
would become visible through kernel tracepoints alone.}
When all four kernel events are present (full attack chain), both IPGs score
\textsc{Malicious} ($\geq 0.92$); TLS interception provides no additional
classification benefit at that stage, confirming that its value lies entirely
in the \emph{early-detection window}.

\cwae{} routes the early ISOLATE verdict to \texttt{SIGKILL}, XDP quarantine,
and an incident report --- all within simulation's software pipeline (no live
kernel enforcement in this environment).
This demonstrates that intent-augmented IPGs prevent prompt-injection APT
chains that syscall-only monitors cannot detect until \emph{after} the attack
has already executed.

\noindent\textbf{Dual-tier pipeline: measured invocation reduction and accuracy.}
Running the dual-tier pipeline (draft threshold $c\geq 0.90$, BENIGN-only
fast-path) on the 14 simulation scenarios with real Ollama models yields the
following measured results (see \texttt{results/evaluations/dual\_tier\_reduction.json}).
Of 14 decisions, \textbf{5 were resolved by the 1B draft model}
(\textbf{35.7\% invocation reduction}) and 9 were escalated to the 8B full model.
The draft fast-path introduces \textbf{two false negatives}: Lateral Movement
(T1210) is accepted as \textsc{Benign} at draft confidence $c=0.99$, and
Valid Accounts (T1078) is accepted as \textsc{Benign} at $c=0.98$ --- both
attack scenarios reach the fast-path exit because the 1B model is overconfident
on subtle living-off-the-land patterns.  The 8B-only pipeline
(Table~\ref{tab:accuracy}) correctly classifies all 14 scenarios.

We report this explicitly as a \emph{measured accuracy--cost Pareto point},
not a free speedup.  The asymmetric fast-path is safe-biased in the
false-positive direction only --- \textsc{Malicious} drafts always escalate
--- but a confidence threshold on an uncalibrated 1B model carries no bound
on the false-\emph{negative} direction, and here it costs two detections
(TPR $1.00\!\to\!0.86$ on these 14 scenarios) for a 35.7\% invocation
reduction.  This is far below our initial projection and is the honest
operating point.  Two principled remedies: (a)~the implemented
\texttt{ConformalFastPath} calibrator, which replaces the hand-set $0.90$
threshold with a split-conformal quantile to bound the false-accept rate by
$\alpha + 1/(n{+}1)$ (mechanism in place and coverage-tested; only the
labeled calibration corpus is deferred to the empirical study); or
(b)~gating the fast-path on agreement of the order-aware entropy and PCABP
layers rather than on draft self-confidence.
Deployments requiring zero false negatives should use the 8B-only path,
which classifies all 14 scenarios correctly.

\subsection{Real Kernel Syscall Trace Evaluation}\label{sec:eval_real}

\noindent\textbf{Capture methodology.}
To complement the simulation results, we evaluate SENTINEL on syscall traces
captured from a real Linux kernel.  Docker Desktop on macOS M5 runs a Linux
virtual machine (kernel 6.10, ARM64); processes inside Docker containers issue
actual Linux kernel calls that are intercepted by the host OS.
We built a \texttt{sentinel-strace} Docker image (ubuntu:22.04 + strace
v5.16) and ran 15~commands---8~attack-mimicking and 7~benign---each in a fresh
container under:
\begin{center}
\texttt{strace -f -tt -T -e trace=execve,openat,connect,listen,fork,clone,mmap,ptrace,setuid}
\end{center}
The attack commands execute real syscall kill-chains inside the container
(credential access, privilege escalation, process injection, exfiltration,
defense evasion) using standard Linux utilities; no destructive action is
taken outside the container.  All traces and the capture script are available
at \texttt{src/python/capture\_real\_traces.sh} and
\texttt{src/python/data/real\_traces/}.

\noindent\textbf{Results.}
Table~\ref{tab:real_eval} reports the per-trace results.  On 15~traces
(8~attack, 7~benign), the aggregate metrics are \textbf{TPR\,=\,1.000,
FPR\,=\,0.286, Accuracy\,=\,0.867} (95\% CI: 0.667--1.000, bootstrapped
$n{=}1000$).  All 8 attack traces are correctly classified as
\textsc{Malicious}.  Two benign traces are false positives:
\texttt{python3} running a JSON workload ($c{=}0.85$) and \texttt{which bash}
($c{=}0.95$) are both classified \textsc{Malicious}; inspection of the IPG
shows the LLM pattern-matches the \texttt{mmap}\,+\,library-load syscall
sequence to T1055 (process injection) and T1027 (obfuscated files), which
are common in \texttt{python3} interpreter startup.
Confidence for true-positive attack traces ranges from 0.83 to 0.93,
reflecting genuine variation in how overtly malicious each syscall pattern
appears to the LLM.  The CI is wide because $n{=}15$ is a small-scale
validation; a larger trace set is needed for publication-quality bounds.

\noindent\textbf{Enforcement tier distribution.}
Under the \cwae{} thresholds (Eq.~\ref{eq:cwae}), the eight true-positive
attack traces span three enforcement tiers: \textsc{Isolate} ($c \geq 0.85$)
fires for T1003+T1071 ($c{=}0.83$, borderline), T1068 ($c{=}0.93$), T1078
($c{=}0.93$), and T1562 ($c{=}0.83$); \textsc{Quarantine}
($0.70 \leq c < 0.85$) fires for T1055 ($c{=}0.83$) and T1003+T1071
combined; \textsc{Kill} ($0.50 \leq c < 0.70$) fires for T1003, T1041,
and T1059 ($c{=}0.83$ each).  The two false positives (python3-json,
which-bash) are classified \textsc{Malicious} at $c{=}0.85$ and
$c{=}0.95$ respectively --- they would trigger \textsc{Isolate} in a
non-dry-run deployment, demonstrating the cost of FPs in a graduated
enforcement system.

\noindent\textbf{TTP labeling on benign traces.}
The classifier returns MITRE TTP annotations on every output, including
benign traces.  Inspection of the JSON results shows the 1B reasoning
chain maps routine \texttt{mmap} + ld.so.cache operations to T1055 (process
injection), T1027 (obfuscated files), and T1087 (account enumeration) on
\texttt{which}, \texttt{find}, and \texttt{python3} traces.  These are
incorrect TTP attributions; however, the final label remains correctly
\textsc{Benign} in all cases.  TTP annotations should be treated as
reliable only when the label is \textsc{Malicious}; benign-trace TTP output
is noise from the LLM's prior over security-relevant patterns.

\subsection{Adversarial Robustness}\label{sec:adv}

A sophisticated attacker aware of \sentinel{} may attempt to stay below
$\theta_{\text{low}}$ by interleaving attack actions with benign operations
to keep sliding-window entropy low and evade LLM invocation.  As shown in
\S\ref{sec:pipeline}, a purely marginal entropy gate is provably blind to
this: a malicious syscall of an already-seen type, interleaved into a
repetitive benign loop, is a pure permutation that the order-invariant
$H_t$ cannot see.  The order-aware gate
(Eq.~\eqref{eq:markov}) closes this hole via the conditional entropy rate
$H_t^{\mathrm{M}}$ and a $(\textit{comm}, s_{t-1}, s_t)$
transition-novelty trigger, generalizing the unigram novel-edge bypass to
the bigram level.

We measure this directly with an ablation on an identical event stream
(\texttt{results/evaluations/entropy\_evasion\_gate.json}).  The detector
first observes a benign baseline of the same process --- so the malicious
syscall \emph{type} and every benign transition are already seen --- after
which a single \texttt{connect()} is interleaved such that only its
\emph{order} (a write$\rightarrow$connect bigram absent from the baseline)
is new.  With the legacy marginal gate the attack \textbf{evades} (marginal
$H_t = 0.87 < \theta_{\text{low}}$, no escalation, false negative); with the
order-aware gate it is \textbf{detected} via the \texttt{novel\_transition}
trigger \emph{while the marginal entropy is still $0.73 < \theta_{\text{low}}$}
--- i.e.\ detection comes purely from the order-aware term, not from the
marginal moving.  A benign control with no injection remains correctly
gate-skipped under both gates, so the new term adds no false positives on
the established baseline.  Controlled injection-ratio studies on DARPA TC
windows are reported alongside provenance classification in \S\ref{sec:eval_darpa}.

\subsection{Trust Boundary Integrity}

The \ebpf{} verifier guarantees that the kernel-resident components cannot
be exploited to crash or corrupt the kernel.  The ring buffer's
per-CPU design prevents buffer-overflow attacks from one process affecting
another's telemetry.  LLM inference runs in an isolated user-space process
with minimal privileges (no network access, \texttt{seccomp-bpf} restricted
to file I/O and \texttt{bpf()} syscall only), preventing an attacker from
pivoting through the inference engine.

\section{Discussion}\label{sec:discuss}
%% ═════════════════════════════════════════════════════════════════════════════

\noindent\textbf{Limitations.}
(i)~LSM hooks and SSL/TLS uprobes require Linux kernel~5.7+ for
\texttt{BPF\_PROG\_TYPE\_LSM} support and libssl symbol availability.
Older kernels fall back to the original tracepoint configuration, losing
TOCTOU resistance.
(ii)~Enforcement latency with live eBPF and Ollama on native Linux has not yet
been measured; current results reflect Docker-based simulation with CPU-bound
Ollama inference (3--12\,s per decision), which is too slow for real-time
blocking.  Quantized models on AVX2 Linux are expected to reduce this
substantially, but this is deferred to the planned empirical study.  The
architecture does not claim sub-millisecond enforcement in the present form.
(iii)~TLS uprobe coverage is limited to processes using dynamically linked
OpenSSL/BoringSSL.  Statically linked AI runtimes (rare in practice) require
Go-specific uprobe symbols (\texttt{crypto/tls.(*Conn).Read}).
(iv)~LLM accuracy depends on pre-trained knowledge of system-administration
semantics; domain-specific programs with unusual syscall sequences may
benefit from targeted QLoRA fine-tuning on Sigma rules and MITRE ATT\&CK
datasets.
(v)~Abstraction Adequacy (Hypothesis~\ref{thm:info}) is an empirical
conjecture, not a proven theorem, and is bounded by the 64-byte argument
truncation and the fixed sensitivity allowlist (threat model,
\S\ref{sec:ipg}); attacks leveraging specific path arguments
(\eg{} overwriting a specific \texttt{cron.d} entry) may require
path-level edge labels and are backstopped by the order-aware gate, PCABP,
and the LTL guardian rather than by the abstraction itself.
(vi)~\textbf{eBPF and TLS uprobe components are design contributions, not
yet empirically validated.}  The kernel-resident components
(\texttt{sentinel.c}, \texttt{sentinel\_tls.c}) require a native Linux~5.7+
host with root access; no evaluation in this paper loads eBPF bytecode.
The TOCTOU-resistance, XDP quarantine, cgroup freeze, and TLS uprobe
interception claims are based on correct implementation of published Linux
kernel APIs and architectural analysis; empirical measurement on live
workloads is deferred to the planned bare-metal empirical study.
Similarly, the novel-edge Bloom filter bypass and seccomp-bpf LLM isolation
are implemented in the kernel component but not exercised in evaluation.
(vii)~TTP annotations on \textsc{Benign} outputs are unreliable (see
\S\ref{sec:eval_real}); the 1B draft model hallucinations T1055 and T1027 on
routine file operations.  TTP labels should only be treated as meaningful
evidence when the predicted label is \textsc{Malicious}.

\noindent\textbf{Future Directions.}
(i)~\emph{Closed-Loop LSM Policy Synthesis}: Use LLM-generated reasoning
to automatically synthesize new BPF~LSM policy rules that block the exact
access pattern of each detected incident, enabling \sentinel{} to harden
itself incrementally.
(ii)~\emph{QLoRA Fine-Tuning}: Fine-tune the 1B draft model on a labeled
corpus of \ipg{} graphs paired with MITRE ATT\&CK ground-truth labels,
potentially raising classification accuracy of the 1B draft model
significantly beyond the heuristic mock baseline used in simulation.
(iii)~\emph{Multi-Agent Monitoring}: Scale the TLS uprobe layer to fleets
of cooperating AI agents by correlating \textsc{LLM-Intent} nodes across PIDs,
detecting coordinated prompt injection attacks that distribute their actions
across multiple agent processes.
(iv)~\emph{Draft Model Fine-Tuning}: Fine-tune the 1B draft model on a labeled
\ipg{} corpus to eliminate the false negatives on subtle techniques (T1210
Lateral Movement, T1078 Valid Accounts) observed with the BENIGN fast-path
at $c \geq 0.90$.
(v)~\emph{Federated IPG Sharing}: Propagate anonymized \ipg{} fingerprints
across monitored hosts for collaborative threat intelligence without sharing
raw telemetry.

\section{Conclusion}\label{sec:conclusion}
%% ═════════════════════════════════════════════════════════════════════════════

We presented \sentinel{}, a kernel security framework that closes the semantic
gap between low-level syscall telemetry and high-level attacker intent through
nine synergistic contributions.
\textbf{LSM-eBPF co-design} replaces tracepoints with post-resolution LSM
hooks, eliminating the TOCTOU evasion surface present in all prior eBPF
detectors.
\textbf{Graph-structured prompting via \ipg{}} compresses multi-process
syscall windows into structured YAML graphs---a novel paradigm that reduces
LLM token consumption by 59.8\% at $n{=}20$ events (tiktoken cl100k\_base,
6 real strace traces) while preserving causal semantics.
\textbf{SSL/TLS uprobe-mediated AI agent monitoring} correlates LLM API intent
with kernel actions inside the IPG, enabling detection of prompt-injection-driven
APT chains invisible to syscall-only monitors.
\textbf{Confidence-Weighted Adaptive Enforcement} maps continuous LLM
confidence scores to five graduated kernel responses, replacing the binary
block/allow model of all existing tools.
Evaluated on 14 manually authored simulation scenarios using Llama-3.1-8B
(8B-only path: 100\% classification accuracy), and validated on 15 real
strace traces (TPR\,=\,1.000, FPR\,=\,0.286, Acc\,=\,0.867), \sentinel{}
routes each detection to the appropriate \cwae{} enforcement tier ---
demonstrating that intent-aware, TOCTOU-resistant, AI-agent-aware zero-trust
enforcement is practically deployable on commodity hardware without dedicated
Linux infrastructure.
